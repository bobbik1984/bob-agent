# Bob — Project Vision

> 状态：v0.1 草案，2026-10-28。来源：用户本日确认的定位（见 [DECISIONS](DECISIONS.md) BOB-D-002 至 BOB-D-004），以及两个前身项目原始愿景的整合（差异分析见 `references/historical-plans/2026-10-28_unification_review.md` 第 3 节）。本文描述产品目标，**不代表任何能力已经实现**。

## 一句话

**Bob 是一个属于你自己的个人助理：在电脑和手机上都能用，事情做了一半可以接着做，成果和决定找得回来，模型和工具随时可以换。**

> One Bob, many devices. Work keeps going. You own it.

## 为谁

- **主要用户**：白领与普通开发者，单个用户，名下有几台设备（电脑、手机，可能有一台常开的机器）。
- **不面向**：公司级、多人、重型协同工作平台；多租户 SaaS。
- **第一个用户**：项目作者本人。当前优先级是先把作者自己完整的个人工作环境搭起来（BOB-D-004），再推广为开源产品。

## 解决什么问题

真实工作不是一次问答，而是“背景 → 新信息 → 决定 → 行动 → 成果 → 再决定”的长链。现在这条链被聊天助手、笔记、待办、日历、编程 Agent 和不同设备切碎了：用户要反复交代背景，找不到旧决定，离开电脑就无法继续。

Bob 接管这些**连接与连续性成本**：
- 同一件事在 PC 和手机上是同一份状态；关闭页面、换设备、断网再回来都能接着做；
- 决定、材料和成果版本带来源，可追溯，可纠正；
- 模型、Harness（Codex、AGY、DSH 等）和执行设备都是可替换的资源，Bob 不绑定任何一家。

## 核心体验（目标）

1. **装上就能用**：安装 App，填入自己的模型 Key（BYOK），就可以对话、记录、整理，不需要先架服务器。
2. **结构按需出现**：随手问答和闪念不强制建项目；事情变复杂时，才把它提升为持续推进的 Work，并保留原对话、材料和决定。
3. **跨设备连续**：手机和电脑看到同一件事的同一状态；明确区分“本机已存”“等待发送”“对方已收到”“执行中”“待确认”“未知”。
4. **手机驱动电脑**：在手机上让电脑处理指定文件或工作区，看结果，批准后再导出；电脑不在线时诚实地显示“等待”。
5. **原生工具照用**：坐在电脑前可以继续用原生 IDE、CLI 或 Harness；Bob 是始终在场的那个入口，不是唯一入口。
6. **常驻节点是可选增强**：需要 7×24 执行或随时可达时，可以加一台常开的机器（自己的 PC、NAS 或 VPS），它运行同一个 Bob 内核。

## 原则

- **Continuity over cleverness**：长期连续比单次聪明重要。
- **State over conversation**：工作状态独立于模型会话，聊天记录不是数据库。
- **One truth per item**：每件事任一时刻只有一个权威写入者，交接必须显式。
- **Honest status**：没有证据就显示未知，不假装成功，不静默换模型、换主机、扩大权限。
- **Evidence before acceptance**：生成成果不等于完成，验证和用户确认分开记录。
- **Minimum setup, lightweight delivery**：核心能力不要求用户配置服务器、Python 或 Node；安装包和手机端保持轻量。
- **Replaceable capabilities**：模型、Harness、Runtime 通过窄接口接入；只有出现真实多实现需求时才抽象，不做“一切皆插件”。
- **Evolve, do not rewrite blindly**：前身项目中验证过的能力和资产按证据逐项保留、改造或替换。

## 明确不做

- 不做企业协同、多租户计费或团队权限体系；
- 不做新的 AI IDE、远程桌面或 VS Code Web 替代品；
- 不把所有文件同步到所有设备，也不要求项目上传云端；
- 不承诺“任何项目在任何机器上都能立刻继续”：执行只在工作环境确实存在或可安全迁移时才迁移；
- 不预建插件市场、全自动路由或多 Agent 编队；这些只在真实需求证明后才做。

## 平台

- 桌面：Windows 优先（macOS、Linux 随后），Tauri。
- 手机：**Tauri Android**；iOS 后期再评估（BOB-D-003）。
- 可选常驻节点：无界面运行同一内核（形态见 ARCHITECTURE 中待决的 BOB-D-005）。

## 北极星指标（先采集基线，不预设数值）

- **续接**：换设备、断线或换执行器后能否继续，是否出现重复执行；
- **启动摩擦**：完成一个代表性任务需要多少配置和打断；
- **状态可理解**：用户能否说清卡在哪、是否已发送、下一步谁动手；
- **成果找回**：能否找回指定旧版本，核实来源，并在其基础上继续。
