# Bob — Project Vision

> 状态：用户确认方向，2026-11-11 按 BOB-D-015 修订（在 2026-10-31 BOB-D-012 基础上整合 `bob-bot` 原型验证结论与三层产品线划分；见 [DECISIONS](DECISIONS.md) BOB-D-002 至 BOB-D-015）。本文描述产品目标，**不代表任何能力已经实现**。

## 一句话

**Bob 是一个属于你自己的 Jarvis 级个人助理：帮你把零散的信息变成可以持续推进的事情——随手交代、看得到进度、由你做决定、换设备后也能接着做、以后找得回来。**

> One Bob, many devices. Work keeps going. You own it.

## 产品层次（与设备数量和部署形态解耦，BOB-D-015）

判断产品是否完成的标准，不是“新版是否逐项搬完旧版全部功能”，而是**每一层用户能否用适合自己的复杂度，把事情顺畅做完**：

| 层级 | 用户托付的事 | 默认呈现的完整体验 | 默认隐藏的复杂度 |
|---|---|---|---|
| **L1 个人助理** | 记住、整理、查网页、盯日常、按时提醒 | Jarvis 单一交流窗口（Siri 式流体彩色球 + 可按需增删的手机桌面式小组件）、收集箱、今天、知识/记忆、晨报、云浏览器手机虚拟窗口接管、3 分钟试用的自我改造 | 节点、端口、Harness、终端日志、订阅额度 |
| **L2 工作助理** | 用我电脑上的资料把事做出来，手机与电脑接力 | + 我的电脑状态、授权文件夹处理、周期任务派发、文稿/设计图/网页成果的 **V1→V2 批注与对照修改** | 多节点集群调度、Git 工作树、协议细节 |
| **L3 专业工作台** | 管理多台设备、多种开发 Agent 与长期项目 | + 项目与设备目录、原生会话续聊、并行子代理、断线回执恢复、GPU/海外出口能力借用、可选额度小组件 | 保留专业控制，但按需展开、不强加于首屏 |

两个关键边界：
1. **基础可靠性不属于专业版特权**：本地先存、同步对账、分级审批、凭据加密、月度花费上限（默认 `$10`）与导出恢复是全层共用的承重墙。
2. **部署形态不等于产品等级**：拥有常开 VPS 的白领仍可使用纯粹的 L1 界面；只有一台笔记本的开发者也可启用 L3。`bob-bot`（`prototype/`）长期作为轻量交互与能力研究原型实验室，验证成熟的能力统一归入本主干开发。

## 为谁

- **主要用户**：白领与普通开发者，单个用户，名下有几台设备（电脑、手机，可能有一台常开的机器）。
- **不面向**：公司级、多人、重型协同工作平台；多租户 SaaS。
- **第一个用户**：项目作者本人。当前作者已处于个人集群阶段，但产品必须先满足单实例独立运行，再扩展手机+PC及个人集群（BOB-D-012）。

## 解决什么问题

真实工作不是一次问答，而是“背景 → 新信息 → 决定 → 行动 → 成果 → 再决定”的长链。现在这条链被聊天助手、笔记、待办、日历、编程 Agent 和不同设备切碎了：用户要反复交代背景，找不到旧决定，离开电脑就无法继续。

Bob 接管这些**连接与连续性成本**：
- 同一件事在 PC 和手机上是同一份状态；关闭页面、换设备、断网再回来都能接着做；
- 决定、材料和成果版本带来源，可追溯，可纠正；
- 模型、Harness（Codex、AGY、DSH 等）和执行设备都是可替换的资源，Bob 不绑定任何一家。

## 核心体验（目标）

1. **装上就能用**：手机、PC或Linux/VPS任一实例填入自己的模型Key和API地址，即可独立对话、记录和整理，无须先配对或指定全局Home。浏览器访问已部署实例，是该实例的操作端。
2. **结构按需出现**：随手问答和闪念不强制建项目；事情变复杂时，才把它提升为持续推进的 Work，并保留原对话、材料和决定。
3. **跨设备连续**：显式共享的同一件事按owner/source/version同步；各实例独立私有对话不自动合并。明确区分“本机已存”“等待发送”“对方已收到”“执行中”“待确认”“未知”。
4. **手机驱动电脑**：在手机上让电脑处理指定文件或工作区，看结果，批准后再导出；电脑不在线时诚实地显示“等待”。
5. **原生工具照用**：坐在电脑前可以继续用原生 IDE、CLI 或 Harness；Bob 是始终在场的那个入口，不是唯一入口。
6. **常驻节点是可选增强**：需要 7×24 执行或随时可达时，可以加一台常开的机器（自己的 PC、NAS 或 VPS），它运行同一个 Bob 内核。

## 原则

- **Continuity over cleverness**：长期连续比单次聪明重要。
- **State over conversation**：工作状态独立于模型会话，聊天记录不是数据库。
- **One truth per item**：每件事任一时刻只有一个权威写入者，交接必须显式。
- **Honest status**：没有证据就显示未知，不假装成功，不静默换模型、换主机、扩大权限。
- **Evidence before acceptance**：生成成果不等于完成，验证和用户确认分开记录。
- **Minimum setup, lightweight delivery**：核心能力不要求用户配置服务器、Python 或 Node；安装包和手机端保持轻量。
- **Replaceable capabilities**：模型、Harness、Runtime 通过窄接口接入；只有出现真实多实现需求时才抽象，不做“一切皆插件”。
- **Evolve, do not rewrite blindly**：前身项目中验证过的能力和资产按证据逐项保留、改造或替换。

## 明确不做

- 不做企业协同、多租户计费或团队权限体系；
- 不做新的 AI IDE、远程桌面或 VS Code Web 替代品；
- 不把所有文件同步到所有设备，也不要求项目上传云端；
- 不承诺“任何项目在任何机器上都能立刻继续”：执行只在工作环境确实存在或可安全迁移时才迁移；
- 不预建插件市场、全自动路由或多 Agent 编队；这些只在真实需求证明后才做。

## 平台

- 桌面：Windows 优先（macOS、Linux 随后），Tauri。
- 手机：**Tauri Android**；**iOS 采用 Safari 主屏幕 PWA + APNs Web Push**（连接常驻节点即可获得系统推送与完整 Jarvis 体验，无须单独开发原生 App，见 BOB-D-015；原生 iOS 后期按需再评估）。
- 可选常驻节点：无界面运行同一纯 Rust 内核（`bob-node`，零 Node.js 依赖；形态见 ARCHITECTURE 及 BOB-D-005/012/015）。

## 北极星指标（先采集基线，不预设数值）

- **续接**：换设备、断线或换执行器后能否继续，是否出现重复执行；
- **启动摩擦**：完成一个代表性任务需要多少配置和打断；
- **状态可理解**：用户能否说清卡在哪、是否已发送、下一步谁动手；
- **成果找回**：能否找回指定旧版本，核实来源，并在其基础上继续。
