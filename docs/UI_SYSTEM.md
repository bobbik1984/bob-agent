# Bob 界面系统

本文定义桌面端、Android 与未来轻量输入终端共用的稳定界面规则。页面实验不得另建一套响应式或按钮系统。

## 布局状态

应用只在 `src/layout/layout-mode.js` 维护一套布局判断：

- `terminalKind`：`desktop` 或 `native-mobile`，由实际运行终端决定；
- `viewportShape`：`portrait` 或 `landscape`，由整个应用窗口的长宽决定；
- `layoutMode`：`desktop-wide`、`desktop-compact` 或 `mobile-native`。

各页面通过 Vue injection 消费该状态。组件可以用局部尺寸保护单个控件不溢出，但不得自行决定产品导航或页面信息架构。

## 工作页面

- 工作页面采用最大宽度 1000px 的单一居中内容流；
- 不在项目内容旁永久放置项目侧栏；
- 桌面端与原生手机端共用“概览 / 目标 / 任务 / 决策 / 动态”功能菜单和项目分组，不维护第二套项目信息架构；
- `desktop-wide` 将功能菜单放在左侧栏，复用日程与设置的侧栏二级导航；`desktop-compact` 与 `mobile-native` 将同一菜单放在内容区顶部，复用现有移动顶部导航；
- 顶部功能菜单是页面根容器的第一个子元素，上、左、右三边必须贴合内容区边界；页面留白只作用于菜单下方的业务内容，不得包裹顶部菜单；
- 当前功能视图只有一个共享状态源，窗口宽窄切换时选中项保持不变，侧栏菜单与顶部菜单不会同时出现；
- 选中态严格沿用现有模板：宽屏侧栏为完整背景块，窄屏与手机顶部为主题色实色块，不使用 Work 专属下划线样式；
- 项目标题行本身承担展开/收起操作，收起时显示当前功能视图的内容数量；多个项目允许同时展开，便于全盘对照；
- 工作页不重复口号式标题；桌面端仅通过最大内容宽度和留白适配大屏，手机端保持顶部功能菜单与底部应用导航稳定；
- 外层导航已经表明当前是工作区域时，不再重复显示“项目”标签；
- 项目用圆点表达状态而不使用通用文件夹图标：桌面端当前项目为主题色实心圆，未选中项目为未激活色空心圆；手机端进行中的项目为主题色实心圆，其他状态为空心圆，展开箭头只表达内容是否展开；
- 空状态只在内容流中出现一次。

## 按钮层级

| 角色 | 公共类 | 视觉规则 |
|---|---|---|
| 主要动作 | `.btn .btn-primary` | 中性高对比实心；同一动作组只保留一个主动作 |
| 次要动作 | `.btn .btn-secondary` | 中性描边或透明底 |
| 紧凑动作 | `.btn .btn-compact` | 28px，用于高密度卡片和 Runtime 选项 |
| 选中状态 | `.btn .btn-selected` | 主题色文字、边框与浅底；表达状态而非提交 |
| 危险选项 | `.btn .btn-danger-outline` | 最终不可逆确认前使用红色描边 |
| 最终危险确认 | `.btn .btn-danger` | 下一次点击会真正执行破坏性操作时才使用实心红色 |
| 纯图标动作 | `.btn .btn-icon` | 34px 无底控件，必须提供可访问名称 |

主题色用于选中、当前位置、进度与焦点，不作为普通新建、保存、确认或提交动作的默认填充色。

## Quick Note 悬浮层

- 速记输入条始终以整个可用屏幕为参照水平、垂直居中，保存提示和底部动作不得改变其中心位置；
- 输入条和底部动作组共享同一个响应式宽度，左右边界必须精确对齐；
- 底部动作使用等宽自动网格，支持 3–5 个动作，不使用 `space-between` 把动作推向屏幕边缘；
- 图标、文字和计数胶囊共享垂直中心线；胶囊内数字使用二维居中，不依赖默认文字行高。

## 迁移规则

新组件和本次被修改的组件必须复用公共类，不得在 scoped CSS 中重新定义 `.btn`、`.btn-primary`、`.btn-secondary` 或 `.btn-icon`。旧组件在触及时渐进迁移；大范围视觉重写仍需单独评审。

## 验收

- 桌面横屏、桌面竖屏与原生手机横屏能得到稳定且可解释的布局；
- 明暗主题均保持可读对比度；
- 项目的选中与未选中状态不只依赖文字；
- 键盘焦点可见，纯图标控件具有可访问名称；
- 不增加依赖，生产构建和完整前端测试通过。
