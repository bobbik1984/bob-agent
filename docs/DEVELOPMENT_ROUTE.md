### BP4 外部项目助理接入顺序

先保持入口与业务解耦：传输认证 → 受限应用操作 → 统一内核权限/版本事务；不为每个外部Agent重写项目管理。入口扩展以复用业务操作为退出条件，不能只验证MCP工具能被列出。当前先覆盖关联，其他业务按需纳入，不做全平台重构。
内部资料通道沿此受限应用层推进：先适配 Dashboard `/api/inbox` 的只读分页并标明来源，再接主助理按需调用，最后向获准项目范围的 MCP/Bot 开放。验收包含未授权拒绝、跨项目隔离、撤销立即生效、内容提示注入不获执行权、正文上限及来源不可达提示；Skill 只作调用说明，不授予权限。当前仅完成来源核对，尚未接入主助理或外部 Bot。

沿 Chief of Staff 与对象级权限路线：受限 Bot 主体与授权项目读取 → 显式整理权限及版本冲突/审计 → 本地真实内核闭环 → 对接官方外部工具入口。执行委派不在本轮范围，未来需独立授权合同，不自动继承设备能力。

Exit Gate：只读不能写；跨项目/跨会话越权被拒；撤销与过期立即生效；关联保存重启后可读且重复版本拒绝；Bot 凭据不能调用任何执行 RPC；真实外部客户端握手单独验收。本地通过不等于 Grok/Muse 已接通。消费端连接器和模型 API 是两条不同接入路径。
