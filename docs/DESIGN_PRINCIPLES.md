# Bob — 设计与交互原则

用户确认来源：2026-10-31 当前对话。本文是 App、悬浮窗及网页端共同的设计约束；实现和验收状态见 CURRENT_STAGE，不因写入规范而视为已实现。

## 视觉语言

- 简洁、现代、直观清晰，保持温和的交互反馈；保留正式 Bob 品牌资产。
- 产品导航、按钮、状态、空态、设置和内置文案不使用 emoji 作为图标或装饰；使用统一 SVG 图标。用户正文和模型原始回复不因此被过滤。
- 顶栏连接状态仅显示一个实心圆点，不增加外圈、光晕或设备图标叠加。保留足够的透明点击区域、键盘焦点和可读标签；点击直达设备连接子页。
- 已配对、当前可达、可执行分别表达；绿色不能仅由保存了凭据或完成配对决定。详细原因在点击后的面板中显示。
- 颜色全部来自主题语义变量；新增文字同步中英文。样式克制不能以删除可访问名称或焦点反馈为代价。

## 首次打开与历史恢复

默认：普通 App/网页恢复当前客户端上次明确选中的有效对话；首次进入或原会话不可用时进入空白新对话。空白页不立即创建持久空会话，首次保存/发送时创建。

旧数据导入、后台刷新、服务器重启不能选择会话，也不能修改用户的阅读位置。显式会话链接可定位目标；历史项目继续在列表中可找，不因修复入口而删除。网页客户端选择不能默认被另一客户端覆盖。

验收：导入旧项目后当前选择不变；服务重启保留用户选择；新客户端无旧选择时空白；旧选择被归档时有合理回退；两客户端切换互不抢焦点。

## 悬浮窗：快速记录灵感

核心动作是本地可靠保存。打开时进入轻量新记录；存在未保存草稿时恢复草稿。键入后在输入区下方出现紧凑的归属选择：不关联项目、最近/搜索已有项目、新建项目。关联可选，不阻塞保存，不因选择项目就启动模型或创建开发 Task。

项目选择与草稿一起保存；新项目在确认保存时创建，取消不留下空项目。记录保存后可继续讨论、转为待办或提升为 Work，保持原始来源。输入期间减少其他菜单，但不能隐藏正在进行的保存/失败状态。

模型切换从悬浮窗高频工具中移到设置或高级选项。连接扫码保留在设备入口；拍照记录是另一项能力：拍摄→预览/重拍→保存原图→识别建议→用户校正/确认。识别失败仍能保存照片，不能把识别文本自动当成已确认决定或提醒。相机权限拒绝时提供系统选图入口（实现后才显示可用）。

悬浮窗内部不重复显示 Bob Logo；品牌保留在正式入口。文字编辑器与外层面板只呈现一处克制的焦点反馈，禁止叠加默认亮蓝内圈；按钮仍须保留键盘焦点。图片/识别内容展开后整个面板须保持在动态视口内，全部按钮能滚动触达。

文字、拍照与选图是记录入口；扫码配对只属于“设置 → 设备连接”。照片先保存原件再按用户点击识别，调用前展示已配置的视觉模型与服务去向，不沿用聊天模型作为静默兜底。识别建议可编辑，须明确加入记录；失败保留原图和文字。未配置视觉服务也可保存图片。相机选择由系统能力决定，不能把文件选择器或桌面浏览器测试称作手机相机验收。当前实现和验证边界见 CURRENT_STAGE。

## Agent 修改入口与检查

修改可见 UI 前必读本文、FEATURES 与当前组件。完成时检查无产品装饰 emoji、主题/i18n、无虚假连接状态；以实际浏览器及适用手机操作验证首屏、项目选择、草稿和错误提示。自动扫描排除用户内容与测试数据，检查通过不代替交互验收。
