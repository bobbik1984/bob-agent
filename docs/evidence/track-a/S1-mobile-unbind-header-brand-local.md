# S1 移动端解绑、标题与品牌色本地修复记录

日期：2026-10-02。工作线：`mobile-pc-rebuild`，应用源码版本 0.9.22。此记录只覆盖本地代码与自动化测试；改动尚未进入用户手机上的安装包。

## 触发与范围

用户报告：0.9.22 手机与 0.9.21 PC 可以配对并成功发送指令。这是用户实机观察，不等于同版本双端、撤销、断线或安全边界的完整验收。用户同时报告解绑后仍有红叉、聊天标题偏心、强调色看起来比悬浮 Logo 深。

检查发现设备弹窗的解绑按钮没有状态条件，手机“销毁并重置”红叉仅由本机密钥解锁状态控制；聊天顶栏以左右宽度不等的 flex 区域居中；Logo SVG 的原色和浅色默认强调色都为 `#2776BB`，悬浮球闲置时透明度为 50%。

## 本地修复

- 解绑命令先撤销设备信任与相关会话，配置和设备名册持久化失败会返回错误；前端只在命令成功后移除该设备，并过滤撤销记录。手机没有活动受信任设备时，不再显示多端同步卡片里的红色身份重置入口。
- 聊天顶栏改用左右等宽的网格轨道，标题锚定整个顶栏中心；长标题省略，费用文本在窄屏可省略。
- 新增默认品牌蓝常量并与 SVG 原色对照测试；浅色默认主题引用品牌色变量，失效的历史强调色覆盖被清除，主动选择的有效强调色保留。

## 可复现验证

- 前端直接运行既有 Vitest：13 个文件、68 项通过。
- Rust 解绑专项：2 项通过；Rust 全库：331 项通过、0 失败、1 项原有忽略。
- Vue 单文件组件解析通过；`git diff --check` 无空白错误。
- 当前重建工作区缺失仓库忽略的 `pdfium.dll`、本地模型资源及部分测试 fixture。Rust 测试从原项目复制忽略资源和 fixture 到本工作区，且仅在测试进程以 `TAURI_CONFIG={"bundle":{"resources":[]}}` 跳过未配置的模型资源；没有执行产品构建或修改正式 Tauri 配置。

## 尚未验证

没有新 APK／PC 安装包，也没有在用户手机上对这次 UI 修复重新安装与目视验收。后续同版本双端候选构建时，应在真实手机上检查解绑后红叉消失、重新配对仍可用、标题居中及默认浅色主题色值，并补测撤销后的旧会话不能继续发指令。
