# 跨设备连接：没有自己服务器的用户怎么用

> 稳定知识页。相关决策：BOB-D-006（accepted，设计）。最后核对：2026-10-28。外部事实标注了来源，引用前请重新核对。

## 1 问题

手机要找到电脑，需要满足三件事：**发现**（对方现在在哪个地址）、**穿透**（越过两边的 NAT 或运营商级 NAT）、**兜底**（直连失败时由谁转发）。传统做法是部署一台服务器，但白领通常没有服务器。

还有一个与网络无关的硬约束：**电脑睡眠或关机时，任何方案都连不上它**。这一点只能靠诚实的界面和可选的常开节点解决。

## 2 分层方案（按顺序尝试，界面始终显示当前走的是哪一层）

| 层 | 方式 | 需要服务器吗 | 适用场景 | 局限 |
|---|---|---|---|---|
| L1 | 局域网直连（mDNS 发现，二维码配对） | 不需要 | 在家或在办公室，同一网络 | 离开该网络就失效 |
| L2 | P2P 打洞直连（基于 QUIC，按公钥寻址，例如 iroh；或 WebRTC） | 只需要轻量的发现和协调；不转发数据 | 大部分家庭宽带 | 移动网络的对称 NAT 和 CGNAT 常常打洞失败；成功率需实测 |
| L3 | E2EE 中继兜底 | 需要中继，但中继只能看到密文 | L2 失败、需要实时交互时 | 中继由谁运营、谁付费（见第 3 节） |
| L4 | **用户自己的云盘作为异步信箱**（OneDrive、Google Drive、iCloud、WebDAV/坚果云） | 不需要新服务器，用户已有账号 | “手机交代一件事，电脑稍后处理，结果放回来” | 延迟以秒到分钟计；不适合流式输出；要处理配额和 API 限制；Google Drive 在中国大陆不可用 |
| L5 | 可选常开节点（自己的 PC、NAS 或 VPS，运行同一内核的无界面形态） | 用户自愿提供 | 想要 7×24 可达或执行 | 需要一定的动手能力 |

**关键判断**：Bob 的大部分流量是小消息（指令、事件、摘要、批准），大文件可以留在电脑上，只传结果。所以 **L1 + L2 + L4 组合起来，能在零服务器条件下覆盖大部分日常场景**；L3 改善实时体验；L5 给进阶用户。

## 3 中继（L3）这道坎怎么跨

- **先例是 Syncthing**：全局发现服务器加社区捐赠的中继，传输端到端加密，中继看不到内容。用户不需要知道中继的存在。Bob 可以走同样的路：先由项目方运营一组有公平使用限额的中继，同时允许任何人捐赠或自建，用户可以在设置里替换。
- **iroh 公共中继不能直接当作生产默认**：n0 提供的公共中继免费，但官方定位是开发和测试用，有全局限速，没有 SLA；流量是端到端加密的，但连接元数据（IP、时间、流量）可以被观察到。生产用途需要自建 `iroh-relay`（开源）或购买托管中继（[iroh.computer](https://iroh.computer)，2026-10 检索）。
- **给开发者的一键自建**：Docker 镜像，或免费层的 Serverless（例如 Cloudflare Workers）部署按钮；这对普通开发者可行，对白领仍然偏难，因此不能作为默认路径。
- **Mesh VPN 作为高级选项**：Tailscale 免费个人版或自建 Headscale，适合开发者；对白领来说门槛偏高。

## 4 对本项目的落地顺序

1. **作者个人环境（现在）**：L1，加上作者已有的自建中继和 Headscale（地址只从 cluster-ops `service_map.md` 读取），常开节点作为 L5。全部以 Connection Provider 配置的方式接入。
2. **开源默认（BP6）**：L1 + L2 + L4 开箱即用；L3 默认关闭或使用社区中继，可以替换；L5 以文档和一键脚本提供。
3. **始终诚实**：显示当前连接层级、对端是否在线；对端离线时只允许保存草稿或排队，显示等待原因及最近尝试时间，不承诺无法证实的到达时间；过期或已撤销的意图在恢复连接后不执行。

## 6 WP-03 Connection Provider契约草案

2026-10-29：接口与安全要求设计已获批；当前已有双向TLS和Home授权接收模块，本机套接字验证不等于跨设备网络测量。安全准则见[threat-model](threat-model.md)，投递语义只在[kernel-schema](kernel-schema.md)维护。

Connection Provider负责discover、connect/authenticate、send、lookup_receipt、subscribe(cursor)、close；返回结构化能力与错误，不裁决Task完成。send必须报告confirmed_zero、started_or_possible或durable_receipt，不能将笼统网络错误猜成未发送。协议不兼容与身份变化停止恢复，网络瞬断才退避重试。

配置最小字段：schema_version、home_device_id、authority_epoch、provider_id、enabled、endpoint_ref、peer_identity_ref、credential_ref、allowed_workspace_refs、timeout_ms。私钥与Token仅在vault；地址由cluster-ops登记资料供用户选择后写入设备私有配置，不放源码、文档示例或Git。首次接线前重新核对service_map/node_inventory及现场服务身份，不能用历史文档证明当前可达。

L1的mDNS只是发现，不能以“同一局域网”免除认证；L2与L3同样验证设备身份。L4承载相同加密意图与回执，不同步活动SQLite，上传完成不等于Home收到。L5是可选部署角色，不是第五种传输协议，也不自动接管Home。

个人环境第一条实现建议为现有受控连接Provider＋本地Outbox，先完成一条Windows Home与Android Replica的真实链路。L2具体库和L4云盘接口尚未选定；本页早先关于供应商价格/公共服务限制的引用为历史研究，本轮未重新核实，不作为当前选型证据。开源默认组合设计已按BOB-D-006接受，具体Provider选型及现场验证仍待推进。

当前实现范围：5a1b9eb候选已实现TLS 1.3、短时邀请/PoP/双方确认、App投递/回复接线与Android Keystore，并已安装Pixel；首次跨设备实际配对仍未验收。用户否定默认手工交换JSON连接码，采用下节二维码流程；已有手工入口仅保留为高级诊断。构建、安装、测试与真机接受分别记录在现有CURRENT_STAGE和shell Evidence。


## 7 首次连接的二维码流程（2026-10-29，用户确认）

默认交互固定为：电脑/Home页面点击连接手机→显示短时二维码→手机Bob点击扫码连接并按系统要求授权摄像头→扫码自动确认该设备→手机自动完成安全存储与连接。之后使用已有配对重连，不重复扫码。连接地址、端口、证书JSON不要求普通用户手工输入。

二维码携带Home公开身份、可达候选地址和一次性邀请；不携带私钥、模型密钥或可长期使用的授权。本次用户明确批准以扫码作为设备确认：首个通过邀请与私钥持有证明核验的扫码者自动获得精确设备/会话授权，不再额外核对指纹。仍不接受仅同网或设备自报名称的请求。设备消息访问与有界只读执行在底层分别记录，不开放任意文件修改。过期、取消、身份变化与重放须明确拒绝。

此流程不扩大网络可达性：局域网/已有私有网络用于首版；二维码不能穿透不存在的路由。云端Home页面只有接入同一可信配对后端并可确认原生身份时才能生成有效邀请，不把旧Online网页自动视为统一Home。远程中继沿原路线推进。

摄像头仅在用户点击扫码时启动；图像本机解码，不落盘、不上传、不记录邀请内容。取消、权限拒绝、非Bob二维码与过期码返回可理解的状态。默认QR入口完成前，不能把手工配对测试标成扫码验收。

2026-10-29授权补充：用户明确批准此手机消息访问365天，可由Home撤销。按本次扫码简化授权，首次扫码自动启用当前只读回复，最长1小时；到期后的新执行授权仍独立，不能通过延长设备配对直接延长执行权限。


### 异地使用验收边界（2026-10-29，用户澄清）

同一Wi-Fi不是产品的长期前置条件。用户可能远控Home显示二维码，再在另一地点用手机扫码；正式个人环境必须覆盖不同网络的首次配对和日后重连。现有直连候选仅能使用已有可达局域网/私网，这是真实实现限制，不能描述为“只是方便测试”。局域网通过不能关闭异地使用验收。

沿本页既有L3/Connection Provider路线补公网可达通道；保持Home身份、单一内核和既有授权，不把中继变成另一套任务权威。公网中继的实现、地址配置、访问控制、部署/回退和移动网络验证均须有独立证据；发布或改变公网访问范围须按现有权限门槛执行。二维码邀请本身不等于网络穿透能力。

撤销后重连：用户主动生成新QR并再次扫描，才可为同密钥/同Home/同epoch生成更高revision的新授权；旧记录归档保留，不直接撤销“撤销”。同Home连接配置仅凭新的认证证明且revision递增替换，禁止借扫码静默切换Home或更换设备密钥。
