## F1 基础助理

首屏、连接圆点、无装饰 emoji 与灵感输入归属遵循 [DESIGN_PRINCIPLES](DESIGN_PRINCIPLES.md)。本次实现/发布边界唯一见 CURRENT_STAGE，不以设计规范代替验收。

- 首次启动：添加自己的模型 Provider（BYOK）后即可对话，不要求配置服务器、Host 或 Harness。
- 对话、闪念捕获、历史检索；支持附件和图片（以平台权限为准）。
- Provider 不可用时给出具体原因和最小的下一步，不静默换模型。
- **验收**：在干净的 Windows 和 Android 设备上，从安装到第一次成功对话，全程只需填写 Provider；断网时捕获保存在本地并标为“未发送”。

## F2 跨设备连续

- 手机和 PC 看到同一事项的同一状态；草稿、阅读位置、待批准的上下文都能恢复。
- 发送状态分层显示（见 ARCHITECTURE 不变量 10）；`unknown-send` 先对账，不重发。
- **验收**：PC 发起后关闭，手机接着处理并看到同一状态；重复或乱序消息不产生重复副作用；断线期间排队的意图在恢复后按规则执行或被拒绝，并有解释。

### F1/F2 导航、续聊和设置合同（已有局部实现，完整状态见 CURRENT_STAGE）

- 左侧汉堡展示真实最近对话和项目；支持新建独立对话、新建项目、项目内新对话、切换和继续。项目是组织单位，可有多条对话；无项目对话合法。点击项目展示其对话，不自动发送或创建模型任务。“创建后启动首个会话”和项目内“新建会话”共用执行位置选择。网页支持本机助理，以及已连接且获授权节点报告的 DSH、Claude Code、Codex、AGY、Pi 工作区。后四种工具以用户首条消息启动会话，首轮限制工具权限。已配对 App 通过网页主节点写入，真机交互待验。执行位置归属会话，项目可跨节点；节点实际返回原生会话身份后才显示创建成功。主助理接受显式目标时走同一入口与权限核对。
- 普通本机会话可从侧栏确认删除，删除后退出活动目录与搜索，历史记录保留在数据库中。删除当前会话时回到主助理。主助理、默认会话和远端会话受保护，执行中的会话须等到执行结束。
- 顶栏显示当前对话标题，必要时附所属项目；同名条目保留不同 ID。列表空态、读取失败、未同步分别显示，不用样例数据填充。内部执行临时项目不能不加区分地变成用户项目。
- 每条对话保留原消息/执行/成果引用以及本设备草稿、阅读锚点。切到另一条对话不停止前一条执行；回复回到原对话并显示未读提示。返回旧对话恢复草稿，不把旧草稿发给新会话。
- “继续”同时要求能看到历史和正确承接必要上下文；上下文来自目标会话的已持久化消息和明确材料，记录边界，不能混入别的项目。无原生 resume 时使用有界上下文接续，并诚实区分两者。
- 三点进入设置首页；顶栏连接圆点直接进入同一设置系统的“设备与连接”子页，不再先展示语言等无关项。设备子页可返回设置首页，也可关闭回原会话；Android 返回键/关闭动作一致，保留草稿和阅读位置。

设置按以下职责组织；不是要求一次放满无效按钮：

| 设置分组 | 内容与显示条件 |
|---|---|
| 通用 | 语言、已有主题/跟随系统选项、发送键行为；支持项持久化，未实现项不伪装可用 |
| 设备与连接 | 已配对设备、扫码/展示二维码、最近核对时间、当前连接方式、撤销/解绑；已配对、当前可达与可执行分开 |
| 在线工作服务 | 配置 Online 服务、登录/失效/退出、可用能力、来源与同步状态；入口须对应真实适配器，不把网页登录 Cookie 当 Home 设备证书 |
| 执行与权限 | 当前执行位置、Provider/Harness、请求与观测身份、现有只读/有界许可及有效期；后续额度能力在有真实数据时再加入 |
| 数据与隐私 | 本机保存状态、未送达数量与可用诊断；导出/清理需先实现安全范围，不能因设置改动清除历史或密钥 |
| 关于与诊断 | App版本/构建身份、可复制的脱敏错误信息；不显示Token、二维码载荷或原始凭据 |

通用、设备子页和版本信息已有实现；Online 的认证生命周期与能力提示仍须完成 OL-02–04。其余设置按适配器真实能力开放。

**验收**：两项目各两会话与旧会话均能回访；发送中切换不会串记录；重开后恢复各自草稿及当前选择；只清除已提交版本的草稿；旧对话两轮实际问答可承接，另一对话不串上下文。手机从设备图标一步进入设备子页，三点仍进入设置首页；中英文、明暗与键盘操作通过。详细任务和验证阶段只看 CURRENT_STAGE。

### F1/F2 侧栏的设备、任务视图与离线表现（分组已有实现，跨节点执行待验）

- 对同一批真实对话提供“按项目/任务”和“按设备”两种分组视图，不维护两套身份或复制历史。默认建议按项目/任务，保留用户上次选择；无Task的普通对话进入独立对话区，不强迫新建开发任务。
- 按设备分组表示当前选定执行工作区所在节点，不是“从哪部手机发过消息”。未绑定工作区的对话显示未指定设备；同项目在多机有副本时展示主执行位置和其他副本入口，不克隆成多个项目。原生会话绑定与业务对话身份仍分开。
- 设备离线时，灰化设备徽标和“立即执行”能力，不把整条对话禁用：已缓存历史、成果、草稿仍可打开，可留言并明确显示等待。未缓存内容标明不可用；不得将离线消息显示为模型已接收。
- 每条工作对话显示一句主要原因，如“可继续”“等待电脑上线”“版本待核对”“缺少素材”“需要重新登录”“执行结果待核对”；详情展示设备、版本和最近检查时间。状态不能只靠颜色，设备在线也不代表工作可执行。
- 提供“查看执行位置/版本”入口；符合条件时才展示切换节点动作，显示其影响和准确版本。选择从旧版本另开候选时明确不包含可能留在离线设备上的改动。
- VPS上同一工作区经任意已认证客户端操作，可避免反复搬源码；仍须该对象owner、授权、模型/工具和素材可用，客户端切换不新建执行。不能承诺任意入口或任意端口天然互通。

**验收**：两种分组切换不改变project/task/conversation ID、草稿和历史；设备离线仍可读缓存/保存留言；同commit但未提交改动不同不能标同步；没有交接证据不能自动恢复到另一节点。实现任务分属BP3-01.c与BP4/F6，版本/交接规则唯一见[kernel-schema](wiki/kernel-schema.md)。

## F3 个人事务域

- 日程与待办、Markdown 笔记、决定记录（理由、备选、证据、重审条件），能力继承自旧 App，迁移时逐项裁决去留。
- **验收**：每类数据只有一个权威位置；从旧 App 0.9.x 迁入后可以读回，可以回退。

## F4 手机让 PC 处理文件

- 在手机上选择一台可信 PC 和一个获准的工作区 → 读取指定文档 → 查看简短总结 → 批准后导出成果。
- 选择 PC 只代表选择执行位置，不代表选择本地模型；PC 离线时显示“等待”，不假装在手机上执行。
- **验收**：权限不随视图扩大；导出前需要用户批准；请求、回执、结果可以对账；通过威胁模型审阅（WP-03）。

## F5 Work 与 Harness（含快慢双轨、项目画像胶囊与原生子代理，BOB-D-010）

- 对话中的事项按需提升为 Work，保留原对话、材料和决定的引用，提升本身不扩大权限。
- **项目画像胶囊（Project Context Capsule）防跑偏**：工作区驻留节点提取以 3～8 KB 为预算目标的项目画像胶囊（`AGENTS.md` 规范、代码目录与符号骨架、已生效 `Decisions`/`Memories`、当前待办与上一版成果结论）同步至主账本；在手机/网页等无源码操作端规划《任务卡》时自动注入，提供可追溯的路径和约束依据；执行端仍须核对当前工作树。
- **快慢双轨与原生子代理（Subagent）**：
  - 快轨：日常对话、任务卡拆解及轻量并发子代理（`invoke_subagent`，模型按配置、能力和预算选择，先单只读子代理后并发）直接由 `bob-runtime` 通过正规商业 API（BYOK）内生执行；
  - 慢轨：正式工程任务通过低频结构化《任务卡》或持久会话（外层受控 `tmux` 防断线保活/可旁观容器 + 内层 `native_sessions` 原生 `session_id` 热续接：ACP / `claude --resume` / `codex exec resume` / `agy` + 结构化 JSON 回执落盘，禁止 `send-keys` 刮屏解析）经进程边界交由目标工作区节点的官方 CLI（DSH、Claude Code、Codex、AGY）执行，禁止逆向订阅凭据；避免无意义冷启动是工程策略，许可按供应商分别核验。
- Task、Execution、成果版本（父版本、hash、来源）、Verification、Review；每个 Harness 的 resume、steer、cancel、attachments、artifacts、events、模型观测能力单独列出证据。
- **验收**：无本地源码的操作端能基于项目画像胶囊生成引用真实模块路径与 Decision 的任务卡；原生 Subagent 并发子任务可独立收敛并唤醒主会话；同一事项跨 Harness 续接产生新 Execution，旧版本只读，V1→V2 指定父版本修改。

## F6 可选常开节点与跨节点专长能力互借（BOB-D-010）

- 同一内核以无界面形态（`bob-node`）或桌面宿主形态运行在不同设备上，任意设备均可作为操作端（Operator），并通过 `RuntimeCapabilityManifest` 按权限互借专长能力：
  - **海外模型出口借用（`overseas_model_egress`）**：国内设备可经由已配对的海外常驻节点（如 `VPS2`）代发商业 API 请求，密钥留在节点本地安全存储；
  - **独显与实体显示器渲染验证借用（`gpu_display_render`）**：无头云端节点或轻薄本可将需要 GPU / 实体屏幕的验证步骤（如 Godot / Blender / 4K 浏览器实机渲染截图）派发给渲染节点（如 `bobbik-pc`），渲染产物自动作为不可变 `ArtifactVersion` 回传供手机/网页端审片；
  - **24×7 常驻沙箱（`always_on_harness`）**：主力笔记本合盖休眠期间，常开节点可在有效授权范围内继续已派发任务；共享对象写入仍遵守其owner可达性与单写者边界，无关本地对话继续独立运行。
- **验收**：节点重启后状态可恢复；顶栏/设置设备列表真实展示各节点在线状态与可借用能力标签；跨节点模型代理与 `bobbik-pc` 渲染截图回传 V1/V2 闭环通过实测；节点离线时客户端诚实灰化对应受影响能力。

## F7 开源发行

### F1/F3 图片灵感记录验收

文字或图片可单独保存；照片原件先落盘，记录与项目归属原子保存；相同请求重试不产生第二条。拍照不可用时可选图，拒绝/失败不丢已有文字。图片识别使用明确配置的视觉角色，说明发送去向；建议可编辑后加入记录，不自动确认为事实/决定/提醒。刷新恢复草稿，保存后可在知识页回看对应原图。发布与真机状态只见 CURRENT_STAGE。

### F5/F6补充验收边界（BOB-D-011）

- 原生会话直接继续，无须配置额外BYOK规划模型；任务卡仅在需要委派/跨工具时组装，不增加Chat/Work或快慢轨必选菜单。
- 同项目不同Workspace、dirty变化和过期胶囊不得串上下文；新增文件路径可声明后由现场核验。
- 单执行者V1/V2可先交付；子代理和节点借用未验时明确缺口。目标owner离线请求与已授权在途执行分别呈现。
- 能力声明不代表已授权/当前可用；渲染图不代替几何/功能检查，供应商模型身份缺证据仍为unknown。

### 默认助理与对象归属（BOB-D-012）

每个实例有自身持久助理Conversation；页面重开保留历史和草稿。模型使用本实例的用户配置。普通讨论直接回复；用户明确要求向一个既有会话派活时，以真实连接与原生session身份关联，目录不完整或存在歧义时不派发。发送原始用户正文，不能由模型建议扩大权限或替换目标。远端回执未知时只核对，不自动重发；结果按原生request/turn关联回到助理，并能进入原会话查看来源。原生会话继续保留源节点权威，不因展示在助理中改归属。

验收分开记录：单实例独立对话、双端共享、集群派发、原生手机操作；网页通过不代表APK或所有权迁移已通过。当前实现范围只见CURRENT_STAGE，后续共享对象owner迁移沿既有BP4/F6推进。


### F2/F5 节点文件阅读验收边界

原会话中的文件引用保持connection/session/path归属；图片可解码、文本可阅读并下载，关闭恢复阅读位置/草稿/焦点；当前读取与历史ArtifactVersion明确区分。首批网页只读预览发布事实见CURRENT_STAGE，不能据此关闭跨端附件、完整网页依赖包或不可变历史成果验收。


### F2/F5 长会话阅读验收补充

网页首次最近10条、向上更早10条、原生游标去重与替换、阅读位置/草稿保留、输入区固定和无变化轻量查询已用真实Winter Shelter验证并上线。DSH原生页包含工具记录，传输量仍有优化空间；预算耗尽可不足10条，不无限取历史。Tauri/真机与历史成果快照仍待验，详见 CURRENT_STAGE 与 dsh-paging Evidence。

### F2 / F5 / F6 补充验收：设备入口与项目双视图（待实现验收）

1. 用户添加一次设备地址并认证，即可看到其已授权Harness及独立可用状态；无需为每个CLI配置公网端口。认证失败、未安装、未登录、离线和忙碌可区分。
2. 同一项目下可见手机助理讨论、节点DSH/Claude开发及另一节点研究，条目显示设备和工具；切换设备视图仍是相同会话，选择后进入原session。
3. 可确认、纠正或解除项目关联，保留原历史、草稿、成果来源；同名但不同项目不得自动合并。关联刷新/重启后仍在，共享关联按Owner版本处理冲突。
4. 旧DSH直连迁入设备入口时不重复生成会话或要求无故重配令牌。节点离线可读缓存，发送明确等待/失败；未知回执先核对，不能自动重发。
5. 目标节点断线/恢复后可核对原执行及结果，取消证实目标进程终止；跨工具不冒充原生续接，跨设备写入须通过既有交接门。

### F2 / F5 会话阅读、成果预览返回与真实流式交互验收（2026-11-02 用户确认）

1. **成果预览返回与嵌套状态栈（缺陷优先修复）**：
   - 预览页左上角提供明确的返回按钮，并遵守顶部安全区避开手机系统状态栏；右上角关闭按钮可保留，但不得作为唯一出口。
   - Android 系统返回键/边缘返回手势、以及浏览器后退（History `popstate`）均优先关闭当前预览回到原会话，不得直接退出 Bob 应用或离开站点。
   - 图片放大、子层详情等嵌套预览状态须按栈逐层返回（先关放大层，再关成果预览，最后回会话）。
   - 关闭预览返回后直接恢复原会话阅读滚动位置与未发草稿，禁止重新加载或重置整个会话。
2. **进入旧会话：瞬时缓存恢复与后台增量同步状态机**：
   - 进入旧会话立即恢复上次读到的消息正文与成果预览缓存；首次进入会话默认定位至最新消息。
   - 角落状态统一流转：`正在检查更新…` → 确认远端有新记录时显示 `正在同步…`（仅增量补充变化记录，不整页闪烁重建） → 同步完成后提示短暂出现随即消失；连接失败则显示 `暂未连接，正在显示上次记录`，完整保留已显示正文与输入草稿。
   - 当用户正在向上翻看历史消息（不在底部锚点）时，新消息到达绝不强行拉回底部，改为显示 `有新消息` 浮动按钮供点击跳转。
3. **消息时间与 Markdown 复制轻量操作区**：
   - 每条消息提供轻量操作区：显示消息实际发生时间，跨天显示日期；缺少可靠时间戳时诚实省略，绝不编造当前时间或假时间。
   - 复制按钮默认复制消息正文并保留原始 Markdown 格式，便于直接粘贴至其他工具。
   - 桌面端支持悬停（hover）显现，手机端保持清晰易发现、易点击；用户消息与助手回复继续通过间距与面层背景区分，不增加厚重边框或繁琐装饰。
4. **真实流式输出与发送/执行全阶段反馈**：
   - 按各 Harness / 模型接口的真实能力呈现：接口支持增量推送（SSE / `stream-json`）时逐段流式展示，并在断线重连后接着补齐剩余增量；接口仅能返回完整消息时，诚实显示“正在处理”状态，完成后一次性展示，**严禁前端用定时器模拟假打字效果**。
   - 状态严格按真实凭据推进：`正在发送／等待接收`（刚点击发送、未获对端接收确认前） → `已接收`（`peer_accepted`） → `处理中`（收到实际执行状态后才可显示“正在思考/处理中”） → `回复中`（收到首段增量流） → `完成`；网络断线与发送结果未知（`unknown_send`）单独提示并走对账恢复，不混同于正常处理。
