# Bob 产品愿景

> **愿景成熟度：探索中** · 建立于 2026-08-09

## 愿景

Bob 要成为普通白领最容易开始使用、也最愿意长期使用的个人智能助理。

用户只需说一句话或分享一份内容，Bob 就能理解意图，把它转化为知识、灵感、待办、日程或可以持续推进的目标；并在长期使用中逐渐理解用户，帮助用户从“想到、看到、记下”一路走到“安排好、完成并沉淀”。

## 面对谁

Bob 服务于每天面对大量信息、想法、任务和日程，但不愿学习复杂 AI 配置与工作流的普通白领。他们希望获得真正有连续性的个人助理，而不是另一个需要维护的工具。

## 解决什么痛点

现有知识库、待办、日历和 AI 助手彼此割裂。用户必须自己判断信息放在哪里、反复整理、重复说明背景，并在多个工具之间推动事情完成；许多 Agent 产品还要求安装环境、配置 MCP 或理解复杂的执行概念。

Bob 要把这些组织和连接成本交给 AI：统一接收信息，提炼和归类，适时提醒，自动拆解复杂目标，并以可理解、可控制、可恢复的方式持续执行。

## 与谁竞争

Bob 的竞争对象不只是 ChatGPT、Claude、Gemini 等通用 AI 助手，也包括 Notion、Obsidian、Todoist、日历和各种自动化工具组成的碎片化工作流。

Bob 不追求在编程上超过 Codex，也不追求在终端操作上超过 Claude Code。它的差异化是：**面向普通白领，把知识、行动、长期记忆和跨端体验统一起来，同时把安装与配置摩擦降到最低。**

## 理想状态

用户安装 Bob，选择一个受支持的大模型并填入 API Key，就可以立即开始。之后无论在 PC 还是手机上，用户都只需要自然表达；Bob 会判断应该回答、记录、提醒还是执行，并清楚展示自己理解了什么、正在做什么、结果是否可靠。

随着时间推移，Bob 会基于有来源、可纠正的记忆越来越了解用户，让用户越来越少整理、越来越少配置、越来越少重复说明，却能更稳定地把事情做完。

## 不可偏离的战略原则

- **最小设置**：核心能力不要求用户配置复杂 MCP 或额外运行环境。
- **轻量交付**：PC 保持零外部运行时并支持绿色使用；Android 不增加沉重依赖；安装包体积是核心竞争力。
- **自然入口**：用户表达意图，不负责理解系统模块、DAG 或模型路由。
- **知识与行动统一**：收藏、知识、灵感、待办、日程和目标属于同一个连续系统。
- **越用越懂但不武断**：用户理解必须有来源、置信度和纠正机制，收藏的观点不等于用户本人的观点。
- **自动但可控**：复杂任务可以自主拆解和推进，但过程必须可查看、可暂停、可恢复，重要操作必须确认。
- **多端是同一个 Bob**：PC 与手机共享一致的信息、状态和记忆，连接或同步失败必须能准确定位。

## 边界

任何新方向如果改变了目标客户、核心痛点、低摩擦定位或上述战略原则，必须先由用户确认；局部功能和实现方式不应频繁改写本愿景。
