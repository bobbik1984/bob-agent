# A 线：Bob App 安全与恢复收口

状态：计划已确认，实施/验收按下列节点推进；不是发布证明。日期：2026-09-22。

## 目标与独立边界

让用户保留扫码配对、设备选择与自然对话体验，并能可信地下达指令、审批、停止和恢复工作。延续 Phase 6，不新增第二套任务系统。

- A 线拥有 bob-agent 的同步/RPC、工具权限、恢复与审批核心、原生 Bridge、设备与审阅 UI、相关测试及文档。
- 不修改 cloud-agent、VPS3 Core/Caddy/数据库、X1T DSH 服务、DSH Web 登录或正在使用的工作区；不得为 A 线测试启动 B 线生产任务。
- B 线独立排期见 [Online/X1T 计划](../../../../cloud-agent/docs/plans/2026-09-22-track-b-x1t-dsh.md)。A1–A4 不依赖 B 线完成；B 线也不等待 App 发布。
- 公共执行契约由 B1 唯一维护；A5 仅按版本消费，差异以变更请求提交给 B 线，不私自复制或改变字段语义。每次任务仅有一个控制端和一个工作区写入者。

## 开发步骤与完成判据

| 节点 | 前置 | 具体工作 | 节点完成证据 |
|---|---|---|---|
| A1 / P6-H 恢复闭环 | 当前未提交实现先固定审查基线 | 复核生产审批/取消函数；prepared 日志必须成功后才能修改目标；各恢复阶段失败显式报告；启动恢复不得在拷贝失败时删除备份，不得在未核验时清理恢复记录或增加成功计数；处理已提交/未提交、新建/覆盖文件的差异 | 真实生产函数故障注入：日志拒写、恢复受阻、每个阶段崩溃、重复启动；文件/SQLite/回执一致，失败保留可恢复证据；不能仅手工设置布尔值 |
| A2 / SEC-01 设备身份 | A1 可继续修复，A2 可先在隔离测试分支验证 | 发现名册与已验证配对分离；保留扫码，网址与扫码复用同一身份验证；持钥证明绑定会话、请求与目标设备；邀请过期、防重放、撤销生效；公开公钥不能当密码 | 伪造 ID、只持有公钥、重放、过期邀请、撤销设备均拒绝；有效配对无需每条消息重复扫码 |
| A3 / SEC-02/03 传输与数据边界 | A2 身份契约明确 | 分别审计 LAN/Relay/RPC/Web Drop；确定成熟安全传输方案，不自行拼加密原语；清理完整 payload 日志，最小同步字段，凭据不离开执行宿主；失败不静默退回不安全通道 | 各通道明确谁能读到内容、认证/加密的实际保证；脱敏测试和中继可见性检查通过后才恢复 E2EE 声明 |
| A4 / P6-DEVICE 双端验收 | A1–A3 通过，双端候选构建另行授权 | 固定 PC/Android 版本；指令→追问→提案→批准/拒绝→停止→断线/重启恢复；真机体验保持文字/成果优先、细节抽屉 | 关联 request/change/artifact 身份，证明确实写入或拒绝，未知状态不假报成功；记录版本、失败路径和用户最终验收 |
| A5 可选 X1T 客户端 | A4 与 B1 契约冻结、B5 闭环验收 | 添加用户自有地址/扫码，发现 X1T 能力；复用公共执行契约、产物获取与权限请求，不另实现 DSH 工具循环 | App 可以独立使用指定执行服务；Online 任务仍查询 Online 权威，不在 App 本地复制第二个可写任务 |

## 测试、状态、授权

先定向失败测试，再受影响回归，最后候选真机；19/32/44 等既往数字仅为历史报告，不是本计划的新执行证据。节点实现不等于目标环境验收。新证据放入 `docs/evidence/track-a/`，仅保留脱敏回执与版本信息。

本次授权文档/看板，不授权实际安装、重型构建、配对信任迁移、密钥轮换或远端业务变更。执行时遵循项目既有门禁；错误属权、恢复不确定、秘密泄漏或测试越界即停止该节点，不影响 B 线隔离环境。

故障回退以各节点执行前记录的代码/配置基线及测试数据库为依据；禁止重置用户脏工作树或覆盖真实数据库。加密方案和发布路径需要单独记录选择，不能将 Tailscale 或个人域名强制给所有开源用户。
