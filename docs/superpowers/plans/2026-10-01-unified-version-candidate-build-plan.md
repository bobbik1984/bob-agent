# Bob 双端统一版本与候选构建实施清单

依据：[已批准的双端统一版本设计](../specs/2026-10-01-unified-dual-platform-version-and-release-design.md)。本计划不触发打包或发布；功能研发仍按手机→PC 稳定重建计划推进。

1. 将根 `package.json` 作为唯一手工维护的产品版本；提供显式同步命令更新主应用、安装器和锁文件的根包元数据；提供只读校验命令供本地与 CI 使用。
2. 对齐当前 0.9.22 PC 安装器的元数据，不借此宣称 PC 功能已更新或可安装。
3. 两端 CI 只在同一提交上产出标有版本与完整 SHA 的候选 Artifact；候选分支及普通 `main` push 均不得自动写 Release/官网固定入口。下一批双端候选必须使用高于已保留 0.9.23 恢复包的版本号。
4. 自动化覆盖版本漂移、非法版本、候选 Android versionCode 下限及发布门禁；运行现有前端测试与 `git diff --check`。
5. 到达双端启动、可信配对与只读指令真机验收节点后，另设明确的晋级流程：复核同一 SHA 双端产物、签名与哈希，用户确认后才创建版本化 Release 并更新官网固定下载入口。未达到此门禁时保持 Artifact-only。

停止条件：版本清单无法准确定位、同步命令修改了依赖而非仅版本元数据、任一平台 CI 漏过检查、或发布步骤仍可由候选推送自动触发。遇到这些情况停止构建并修复，不用单端包冒充双端候选。
