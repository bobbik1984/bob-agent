# Bob 同步诊断测试页设计

## 目标

创建一个独立、单文件 HTML 测试页，用于大胆试验 Mobile—Relay—PC 三角拓扑、连接状态和同步日志。测试页不接入真实 Tauri API，不修改正式产品逻辑，不增加依赖。

## 核心语义

1. 配对成功只证明身份验证与握手完成，不等于发生过数据同步。
2. Relay 已连接、对端在线、数据同步成功必须是三个独立状态。
3. 主题色表示当前活动或已确认连通；灰色表示未检测、未使用或无法确认。
4. 红色仅用于局部失败提示，不给整个拓扑高饱和染色。
5. 没有数据同步证据时明确显示“连接已建立，尚未发生数据同步”。

## 页面结构

- 顶部：页面标题、亮暗主题切换。
- 左侧：状态场景选择器。
- 中部：放大后的等边三角形拓扑。
- 右侧：三个带文字的状态标签，分别显示 Relay、本机和对端。
- 底部：统一活动时间线，但明确区分“连接事件”和“数据同步”。

## 拓扑视觉

- Relay 位于顶部，Mobile 与 PC 位于底部。
- LAN 使用底边直线；Relay 去程和回程使用平行但错开的有向边。
- 箭头必须完整落在线段内部，不能被节点或 SVG 边界裁切。
- 成功路径使用低饱和主题色；未确认路径使用灰色；失败路径保持灰色，并在失败位置显示小型错误标记和说明。
- 节点只表达设备自身状态，边只表达对应传输路径状态。

## 测试场景

1. 刚完成配对，尚未同步。
2. Relay 已连接，手机离线。
3. LAN 首次同步成功。
4. Relay 完整同步成功。
5. Relay 已接收，但 PC 未响应。
6. PC 已处理，但回程失败。
7. 从未连接、从未同步。

## 日志规则

- 连接事件示例：配对成功、Relay 注册成功、发现对端在线。
- 同步事件示例：开始同步、LAN 不可用、切换 Relay、收到响应、本地写入成功。
- 每个场景至少显示最后确认事实；不得用“消息已发送”代替“同步成功”。
- 空日志只允许出现在“从未连接、从未同步”场景，并附带解释。

## 验收标准

- 320px 宽度仍能看清三节点、五条路径和箭头。
- 红、绿、蓝不再同时争夺视觉注意力。
- 用户无需悬停即可理解状态圆点含义。
- 配对成功场景不会显示数据同步成功。
- 单文件离线打开可用，无外部字体、图标库或脚本依赖。
