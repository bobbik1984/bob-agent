# Bob 手机→PC 协同重建：稳定启动基线设计（2026-10-01）

## 决策与范围

以提交 `a896f53`（v0.9.15）作为已知可启动的产品基线，按用户可验证的能力重新开发，不按 v0.9.16～v0.9.21 的提交顺序合并代码。后续提交用于提取产品需求、协议约束和测试案例；其中票夹与知识图谱 UI 不属于手机→PC 主线。首个可用版本依次交付稳定启动、可信配对、只读文字远程执行；Diff 审批、停止确认与文件写入留给下一版本。

本规格只覆盖第一施工单元：建立可追溯的 v0.9.15 基线并保证 Android 启动不依赖配对、网络、同步或远程执行。它不宣称已找到 v0.9.21 卡屏的精确根因，也不把启动修复等同于 A4 真机验收。

## 方案选择

1. **采用：稳定基线上的小步重建。** 保留 v0.9.15 原始提交与已签名包，另设独立施工分支或工作树。先证明原始包在当前手机环境能启动，再一次只引入一个必要能力；每次引入都跑未配对和已配对冷启动。优点是回归范围小、失败可定位；代价是需逐个重建后续能力。
2. 在 v0.9.21 原地修复。可保留最多现成功能，但 WebView 挂载前停滞的精确触发点尚未查明，改动间耦合难以隔离。
3. 顺序拣选 v0.9.16～v0.9.21 提交。操作看似快，但这些提交混合了同步、无关 UI、构建调整与未奏效的启动补丁，不能作为功能依赖图。

## 架构边界

- **启动壳**仅负责 HTML/WebView 就绪、最小 Vue 根节点挂载、可见的首屏或可恢复错误状态。显示 Logo 不等于启动成功；只有可操作界面已渲染并响应输入才算启动完成。
- **本地状态加载**可在首屏之后异步进行。读取配置、数据库、已配对设备或历史会话失败时，应在界面呈现明确状态，但不得无限期保留启动遮罩。
- **协同服务**包括设备发现、可信会话恢复、局域网探活、Relay 连接和首次同步。它们不能成为 Vue 模块求值、根节点挂载或首屏显示的前置条件。它们的失败只影响协同状态，不使基本聊天界面不可达。
- **Bridge 与 Rust**保持现有 Tauri 架构：Vue 经 `window.electronAPI`/bridge 访问原生能力；原生初始化只执行首屏所必需的有界工作。任何后移初始化必须保留失败结果与取消能力，不能以静默忽略换取“能打开”。
- 第一施工单元不改变配对协议、密钥、数据库 Schema、用户文件或生产中继。手机现有安装和数据不作为试验性降级目标。

## 启动数据流与状态

1. Android 原生 Activity 与 WebView 加载静态资源。
2. 前端入口完成模块求值，创建并挂载最小 Vue 根视图。
3. 首屏显示后，独立调度本地配置/历史加载及协同连接。每项操作分别报告 `idle / loading / ready / unavailable`，不得串行阻断首屏。
4. 配对数据存在时，后台恢复可信设备与同步；PC 离线、网络超时或认证失败时，界面保留可操作性并给出相应的协同错误。绝不把同步失败显示为已完成，也不默默改为手机执行。

阶段标识应覆盖 HTML、入口模块、根视图挂载前后、首屏可交互、协同启动及失败，但只记录阶段码、耗时与非敏感错误类别。不得记录邀请密钥、会话令牌、提示词或用户文件路径。若只能观察到“挂载开始”而没有“挂载完成”，判为前端挂载失败，不能借自动移除 Logo 宣称成功。

## 开发顺序与验收

### S0：冻结与复现

- 记录 `a896f53`、当前 HEAD、工作树状态、现有 v0.9.15 APK 的 SHA-256 和签名证书指纹；保护当前分支与已装手机数据。
- 对比原始 v0.9.15 与当前失败版本的实际真机冷启动记录。若 v0.9.15 在同一环境也失败，停止“已知良好基线”假设，先调查设备或数据迁移因素。
- 不用覆盖安装旧 APK 到当前较新版本；使用不触碰现有安装数据的验证方式，经单独确认后才进行设备操作。

### S1：首屏与后台职责隔离

- 只调整对启动有直接影响的入口、根视图、bridge 初始化与原生启动职责；不得顺带移植 v0.9.17 UI 或重构整套聊天界面。
- 自动化覆盖：协同调用永不返回、配置读取失败、PC 离线、无配对记录、异常同步回执、前端挂载异常。断言首屏可达，错误真实呈现，没有虚假完成状态。
- Windows 桌面端基本启动与既有聊天功能不得退化；Android 真机未验收前状态仅为“代码与测试就绪”。

### S1 出口门槛

同一可追溯候选包在真实 Android 手机上分别以未配对和已配对状态完成多次冷启动、进程结束后重启、断网启动、PC 离线启动；每次均进入可操作界面。核验阶段日志不泄密。任一场景仍停在静态 Logo、只有进程存活而界面不可操作、或同步失败被标成成功，S1 不通过，不进入可信配对重建。

## 后续单元接口

- **S2 可信配对**：QR 与手动链接共用一次性邀请和持钥证明；发现设备不等于受信任；失败不产生半配对状态。S2 的入口只能在 S1 首屏后触发。
- **S3 只读远程执行**：当前对话粘性选择 PC；手机发送只读文字指令，PC 返回文字、状态与错误；连续追问保持上下文；离线不静默回退。模型密钥留在执行设备。S3 不含文件修改。
- **S4 可控修改及以后**：Diff 审批、取消 Ack、产物与工作记录另立规格，不得为其预先让启动壳依赖执行引擎。

## 停止条件与权限边界

发现 v0.9.15 在当前设备无法复现正常启动、签名不一致、需要卸载/清空应用数据、要修改生产密钥或数据库、需要额外依赖/Schema 迁移、或要执行重型构建/云端发布时，先停止相应操作并给出证据与选择。规格获批不自动授权这些动作。代码测试、真实手机启动、双端业务验收与正式发布分别记录，不相互替代。
