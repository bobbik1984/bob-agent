# 移动端解绑、标题居中与品牌蓝修复设计

## 目标与边界

在同一 Bob 代码包内修复三个移动端问题：解绑后仍可见解绑操作、聊天标题偏离屏幕中心、默认强调色与 Logo 原色不一致。保持现有跨端指令协议与已观察到的 0.9.22 手机 → 0.9.21 PC 成功路径不变。本次不打包、不发布，也不把这一次成功调用表述为完整跨端验收。

## 已核对事实

- `public/bob_logo.svg` 与 `public/bob_bob.svg` 的填充色为 `#2776BB`。悬浮气泡闲置时 `opacity: 0.5`，因此截图中的显示色更浅，不作为品牌色取样。
- 设置页设备列表目前只排除本机 ID，解绑按钮对剩余设备无条件展示。解绑命令还会清除注册表、配对配置并撤销数据库中的信任和会话，但其中部分持久化错误被忽略，可能返回假成功。
- 聊天顶栏用 flex 排列。左侧菜单与右侧费用／日程按钮宽度不同，标题只在两者之间居中，不在整个视口居中。
- 浅色主题默认 `--user-accent` 已是 `#2776BB`，但运行时保存的 `accentColor` 可以覆盖它。选中态通过 `--user-accent` 着色。

## 方案选择

可选的表面修补是解绑后仅隐藏按钮、给标题手动加偏移、对截图颜色取样。它改动少，但会掩盖后端解绑失败、随右侧控件宽度变化再次偏移，并制造第二个品牌蓝。

采用状态与布局修复：解绑成功以持久化结果为准；活动设备列表只显示仍可操作的设备；标题按视口中心定位；以 Logo SVG 的 `#2776BB` 作为默认品牌色唯一依据。保留用户主动切换主题／强调色的设置，不重写已有个人选择。

## 具体行为

1. 用户确认解绑后，只有注册表、配对配置、数据库信任／会话撤销都成功才返回成功。若任一步失败，明确报错并重新读取实际状态，不显示虚假的“已解绑”。成功后清除当前绑定设备的活动入口，设备列表立即刷新；没有可操作设备时关闭设备弹窗。数据库里的撤销审计记录保留，但不在活动设备列表显示解绑按钮。
2. 标题（包括编辑输入框）以顶部栏视口中心为锚点。左侧菜单和右侧费用／日程仍在原位置且保持触控面积；长标题省略，不覆盖两侧控件。横竖屏与费用有无两种状态都保持真正居中。
3. 默认主题交互强调色固定采用 SVG 原色 `#2776BB`，相关 RGB 值保持 `39, 118, 187` 一致。悬浮气泡可因闲置透明度显浅；主题或用户主动选的强调色不被重置。若运行时缺少有效强调色，回退到品牌原色而不是另一种蓝。颜色仍通过主题变量传递，不在组件内追加散落的色值。

## 验收

- 自动化覆盖：解绑成功后列表无该设备／无解绑按钮；持久化失败不能假成功；标题在左右控件不等宽时仍处于视口中心；默认品牌色契约与 SVG 色值一致，主题覆盖仍可用。
- 运行受影响的前端与 Rust 测试、静态检查及 `git diff --check`。不运行重型本地构建。
- 如有可用的移动端预览／真机候选，再目视检查标题、颜色和解绑后的页面。没有重新打包安装时，仅报告代码与测试已验证，不声称手机上的旧安装包已修复。
