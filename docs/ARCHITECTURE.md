# Bob — Architecture

> 本文记录已接受的边界与待决方案；目标架构图不代表全部已实现。当前实现是 bob-kernel/bob-transport + Windows/Android Tauri，已包含 bob-runtime/bob-node；Online兼容接口与DSH原生会话接入是不同能力，后者网页路径已部分验证，手机原生接线仍待补齐。事实与验证范围见 [CURRENT_STAGE](CURRENT_STAGE.md)，代码位置见 [COMPONENT_MAP](COMPONENT_MAP.md)，决策理由见 [DECISIONS](DECISIONS.md)。

## 1 已接受的不变量

来源：用户在本项目中的确认（BOB-D-001 至 BOB-D-005、BOB-D-008），以及两个前身项目中**都已接受、并且与本项目定位一致**的原则（ONL 宪法第 1–12 条、APP-D-008 / D-009 / D-016 / D-018）。

1. **One truth per item**：每个对象任一时刻只有一个权威写入者；交接必须显式，并保留来源（ONL 宪法 11）。
2. **Project ≠ Workspace ≠ Host**：项目是逻辑主体；工作区是某台主机上的目录；只同步工作，不同步全部硬盘（ONL 宪法 1）。
3. **Task > Execution**：换模型、换 Harness、换主机都创建新的 Execution，保留同一个事项身份；不在原 Execution 内“换脑”（ONL 宪法 2、8）。
4. **Execution completed ≠ Task completed**：生成、登记、验证、审阅、接受分开记录（ONL 宪法 4，ONL-D-WEB-01）。
5. **Transcript ≠ Memory**：会话记录只是证据；长期记忆有来源、可检查、可纠正、可遗忘（ONL 宪法 5，APP-D-019）。
6. **Capability is real only when available**：能力只有在当前环境真实可用时才出现；降级必须诚实，不静默回退（APP-D-016，ONL 宪法 9、12）。
7. **Requested / Resolved / Observed**：模型和运行配置分开记录；没有观测证据就是 `unknown`。
8. **三个信任域分离**：设备配对、操作授权、Provider 认证相互独立。配对成功不等于可以写文件，有模型 Key 不等于批准执行。
9. **凭据留在边缘**：凭据存放在设备的系统安全存储（Windows DPAPI、Android Keystore）或执行主机本地；不同步、不进日志、不进成果、不进上下文包。
10. **懒式响应、静默预热与本地接纳（BOB-D-008）**：输入框focus/input（15秒冷却）静默预热；与后台投递共享Rust内核中的单飞唤醒和新watch。UI发送先将消息与intent_outbox在同一个磁盘事务中提交，提交成功立即上屏/清空本次草稿，不等网络。已证明零请求字节的失败是not_dispatched，可自动重连；已经或可能出网但无ACK才是unknown_send，先对账，不能盲目重派。磁盘失败保留草稿，禁止内存库降级后假称保存成功。Outbox的peer_accepted只表示对方持久接纳；running、检查及人审状态来自各自领域对象，不混成一条发送状态。完整状态图、崩溃边界与O01–O15验收仅在[kernel-schema](wiki/kernel-schema.md)维护。
11. **原始证据不被覆盖**：摘要、检索、纠正都不能覆盖原始捕获和证据。
12. **个人基础设施不进代码**：域名、IP、节点只能经配置或 Provider 注入（BOB-D-004）。

## 3 数据所有权模型（BOB-D-012：实例独立，对象有主）

- 手机、PC、Linux/VPS均可独立运行同一Rust内核，配置自己的模型服务并持久对话，无需先连接其他设备。
- 浏览器操作其所连接的实例；服务器常开是可用性能力，不是全局所有权。手机+PC与个人集群是渐进组合。
- 每个对象有唯一owner instance、来源命名空间、原始ID及版本。当前实例创建的对象由本实例负责；共享副本与跨实例意图保留来源，不全盘合并活动数据库。
- 现有Home/Replica仅管理已配置共享关系；对远端owner对象的写入遵守认证、授权、expected_version、幂等与fencing。owner离线不阻止无关的本地对话和捕获。
- DSH会话仍由DSH管理；Bob保存connection_id/session_id关联及有来源的回执。Project、Workspace、Host不互相等同；GitHub副本不等于所有最新文件或任务状态。
- 所有权迁移须显式核对版本、在途/未知执行、恢复与撤销，不自动多主；凭据不随普通同步迁移。
- 实现边界：现有单实例内核和配对机制继续使用；对象级跨实例联邦为待实施契约，不能因文档修订宣称迁移已完成。

## 4 扩展边界与待决事项

### 多节点工作与执行策略（BOB-D-010，按BOB-D-011修订）

操作端、各实例的对象账本、工作区执行节点分离；项目可驻留一个节点，跨节点写入通过明确检查点和写入权交接。节点能力需分别记录支持、授权、可达和验证证据，不能由主机名字推断。

API助理与原生Harness共享连续对话入口。已有原生会话直接延续，不强制经过API规划；跨工具委派才按需装配上下文和任务卡。kernel持领域状态/权限，runtime负责调用与有界调度；不另造任务生命周期。详细协议唯一见[kernel-schema §10](wiki/kernel-schema.md#10-多节点能力互借项目画像胶囊与快慢双轨子代理契约2026-10-31bob-d-010)。

对象owner不可达时，仅该对象的远端写入排队；本地独立工作继续。已有授权执行可在有效范围内继续并暂存回执。常开节点不自动获得其他实例对象所有权。对象交接、旧owner恢复与fencing需单独验证；实施队列见CURRENT_STAGE §3。模型出口与渲染能力不得绕过凭据隔离或B4原有门槛。

### 侧栏与现有 Online 的接入边界（部分实现）

导航是同一 Rust 内核 projects / conversations 的查询投影，不是 Vue 自建的一套列表库。逻辑会话、执行尝试与 Harness 原生会话分别保留身份；设置打开位置、当前选择、草稿和阅读位置是设备视图状态，不承担消息或授权真相源。细则见 [kernel-schema](wiki/kernel-schema.md) 的多会话增量合同。

设备配对权限不能通过 UI 选择扩展到未获准的 conversation。新会话需在既有设备认证下由该对象的owner持久接纳和建立明确归属；旧消息、在途执行和回执按原 ID 归档，不能使用“当前选中会话”重新解释它们。

现有 Online 是过渡期外部工作服务，不自动成为本 App 的 Home。兼容 Provider 保存来源命名空间与原始项目/任务/执行/成果 ID，先读取再实施受控续聊；既不合并活动数据库，也不把 PC 配对凭据交给 Online。新内核的本地对象由创建它的实例管理，外部对象在迁移前由原服务负责，同一对象不能双写。具体认证、路由和公网边界见 [connectivity §8](wiki/connectivity.md#8-现有-online-接入与公网连接的分工)。

## 5 安全边界（必过门）

手机远程读取 PC 文件（F4）、Harness 在个人电脑上执行，是攻击面最大的两条路径。上线前必须完成 WP-03 威胁模型：设备配对与吊销、操作授权范围、默认拒绝的执行环境、重放防护、日志脱敏，以及丢失手机时的处置。

## 已实现路径与验收边界

连接/安全设计见 [connectivity](wiki/connectivity.md) 与 [threat-model](wiki/threat-model.md)。本地 Outbox、单飞唤醒、Home 接收、原生 IPC 与私网 Pixel 配对/回复均已有实现及不同层次证据；公网、当前工作区增量与完整产品验收仍分开记录。2026-10-28/29 的未接线历史见既有 Evidence，不继续作为当前状态。

### 当前增量与已接受边界的冲突（2026-10-31 审计，尚未修复）

未提交的 PeerSync 共享配置会读取 vault 凭据并放入同步包；与不变量9的“不同步”冲突。Home 端共享配置合并调用位于包级接收校验之前，需验证失败无副作用。Online 凭据已使用 vault 槽位，但普通模型中心快照会向 Vue 返回原值。当前没有真实泄漏证据，也未读取运行凭据；这属于代码路径审查发现，不能因 mTLS 存在就视为产品策略已获批准。

按现行规则，普通同步只传非秘密配置，认证请求保留在受控原生端；跨设备凭据转移若作为便利功能须先明确范围/设备/撤销与威胁模型，并记录决定。修复及验收见 CURRENT_STAGE S0；本次文档审查不修改已接受决策或业务代码。

### BP2回复证据边界

本机官方CLI登录与远端Home设备认证分开。早期`external_cli_probe`只记录独立CLI验证结果，回复使用现有messages/evidence/evidence_links，不产生虚假的Task/Execution或Home回执；这段历史不能作为Bob按钮派发证据。原生历史接口输出role/reply_to；普通前端不得调用回复导入。

当前Windows本机只读Runner已绑定既有Task/Execution：消息先持久接纳，再按request_id登记唯一执行、工作区租约与预定Job归属；本机接管意图不得同时进入通用远端派发。官方CLI由专用worker启动，worker先加入设置了关闭即终止的Windows Job，持久启动登记成功后才释放输入。未配置可执行文件、启动登记失败或Job绑定失败不得降级裸跑；此路径只允许空白临时工作区的只读文本回复，不代表一般工具或真实仓库隔离已获验收。

取消请求与停止确认分开记录；超时、取消和退出均检查整个Job的子进程清理结果，未确认时保持unknown与占用。回复只有在有效成功事件、正常退出及清理确认后，才与执行终态和证据同事务落盘。重启不自动重放模型：以预定Job身份核对旧进程是否消失，再从持久完成回执恢复；没有结果证据则记录中断失败，不虚构回复。完成回执临时文件恢复与编码后大小上限已补齐专项回归，详见当前施工合同与Evidence。

UI发送、执行状态、取消与历史读取均经原生命令调用同一内核；成功回复来源标为正式codex_execution，与external_cli_probe区分。实际原生命令模型往返和GUI点击属于不同验收层；当前进展由CURRENT_STAGE记录。Home授权、TLS传输、首次配对及Android已有实现与私网证据；异地公网和当前增量仍需分别验证。

### Home接收边界

可信传输完成标准双向TLS身份验证后，按本地Home身份/epoch及实际证书指纹获取内核授权上下文；请求体不能自行声明可信身份。授权绑定设备、密钥引用、精确会话、版本与有效期，每次业务操作重新核对，撤销使旧上下文失效。接收/回执查询与执行授权分离。

传输使用TLS 1.3正常证书链及域名验证，并额外绑定已配对证书指纹；禁止明文降级、首次使用即信任及早期数据。网络I/O有绝对期限与帧上限，但不声称可强制中断任意数据库回调。可能已发送却未得到回执必须查询原请求，缺失回执仍不构成安全重派证明。

Windows原生vault仅接受可信app-data目录，使用当前用户DPAPI固定槽位、拒绝覆盖/重解析路径/明文回退。不对前端暴露任意文件路径；DPAPI不能抵御同用户恶意进程。Android Keystore、身份签发与首次配对已有实现；真实证据范围见 CURRENT_STAGE。不以测试证书填补未验证的授权边界。

### 灵感图片与识别边界（F1/F3）

原件属于内核数据：`capture_media` 保存不可变原始 bytes 与内容哈希，`capture_media_links` 将 capture 关联原件；不复用工程 Artifact/Execution 生命周期。图片上传与最终文字保存分离，最终 capture/可选项目笔记/原图关联为同一事务。草稿媒体引用和未采纳建议为客户端状态。

视觉识别属于 Runtime/宿主能力，使用视觉角色和当前节点凭据存储；内核不持有提供方密钥、不自行调用模型。用户主动识别，后端核对实际配置仍与披露目标一致，不自动改用其他模型。返回文字是建议，提供方模型字段存在时与请求模型分开。Node 请求体通过子进程 stdin 传递，禁止把图像或密钥置于命令行参数；Tauri 复用已有宿主 HTTP 传输。原图目前不进入 personal_ops 同步包，界面不得宣称图片跨端已同步。

### 原生会话来源与历史导入

旧平台导入项目保留来源，不是实时节点目录。DSH的connection_id与session_id共同定位原生会话；目录路径是工作区线索，不能凭同名自动合并项目。DSH仍是原生历史的权威，Bob保存关联与有来源的缓存。目录投影不能生成执行、检查通过或成果证据。认证传输与持久发送接纳尚待接线，不能用只读解析模块宣称已完成续聊。

### 默认助理入口与原生会话直达（2026-10-31 用户确认）

默认入口为持续的助理Conversation，不要求先选择项目或执行Session。当前选定的助理模型解释意图并提出关联；模型输出不是执行授权。用户可直接进入指定connection_id/session_id，直达模式禁止自动改派。切换助理模型不改变项目、任务或执行会话身份。

主对话保留原始请求、关联理由及执行引用；原生历史仍由DSH等服务持有，不复制为另一份权威。明确的执行要求和唯一目标可在已有权限范围内派发；讨论、目标歧义、离线或权限不足不能自动调用执行者。采用现有对象owner授权、Outbox、Task/Execution和版本体系；去向、接收、执行、失败、成果和人工接受分开显示。结果以来源/版本引用返回助理对话，续改绑定父版。专职Agent只是可选角色，不另建主账本。

实现状态：现有直达链路部分验证；默认助理关联、受控派发及结果回流尚在实施，不能因本节获确认宣称已完成。
